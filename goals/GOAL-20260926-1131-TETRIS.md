# GOAL-20260926-1131-TETRIS: Robot Tetris benchmark with referee scoreboard

## Intent

Robot players — two scripted dummies and one live thinking model — join a Rust Tetris engine as separate plain-text-line programs, play seeded and exactly repeatable games where garbage answers are rejected without breaking play, and a referee command runs a 3-game contest per robot that writes a points-ranked scoreboard.md, so we can say with evidence which AI plays Tetris best.

## Problem

The repository is empty (`README.md` only): there is no Tetris engine, no robot protocol, no robots, and no referee, so nothing today can answer which AI plays Tetris best (user: whole discussion).

## Outcome

Anyone can run one seeded game (`tetris`) or a contest (`referee`) in which dummy-random, dummy-drop, and thinker each play the same 3 games, then read `scoreboard.md` ranking them by points with lines cleared and pieces placed; the same seed replays the same game byte for byte, nonsense or blocked moves are rejected without ending the run, and the live-model robot really plays through its connection settings in `.env`.

## Scope

### In

- Rust Tetris engine: 10-wide by 20-tall board, standard tetrominoes, seeded piece order, one-row slide per answer, game ends when the stack reaches the top
- Line protocol joining external robot programs: the game sends plain-text board state and reads one move word per answer (`left`, `right`, `rotate`, `drop`), rejecting illegal or garbage answers
- Two dummy robots (`dummy-random`, `dummy-drop`) and one live-model robot (`thinker`)
- Optional nudge timer: off by default, on with `--timer 1`, logging `timer nudge`; the thinker's games run with it on so a stuck call cannot freeze play
- `tetris` single-game command and `referee` contest command (3 games per robot, same seeded sequences for all) writing `scoreboard.md`
- Line scoring of 100/300/500/800 proven by four scripted move fixtures

### Out

- Do not build any graphical interface or human keyboard play
- Do not add move words beyond `left`, `right`, `rotate`, `drop`
- Do not add level speed-ups, hold pieces, next-piece previews, or garbage-line attacks between robots
- Do not put the model connection values anywhere outside `.env` and `GOAL-20260926-1131-TETRIS.goal-file-credentials`
- Do not rank robots by anything other than points (ties may share a rank)

## Context

- Constraints: Rust; robots join as separate OS programs exchanging newline-delimited plain text on stdin/stdout; no human play; the live model's connection values (the `DEFAULT_*` names below) live only in the gitignored `.env` (already placed there from `GOAL-20260926-1131-TETRIS.goal-file-credentials` beside this goal — copy them nowhere else)
- Files / systems: cargo workspace with binaries `tetris`, `referee`, `dummy-random`, `dummy-drop`, `thinker`; fixtures `moves-100.moves`, `moves-300.moves`, `moves-500.moves`, `moves-800.moves` at the repo root; `scoreboard.md` written to the working directory; `.env` holding `DEFAULT_BASE_URL`, `DEFAULT_API_KEY`, `DEFAULT_MODEL`, `DEFAULT_API_VERSION`
- Commands: repo is greenfield; the gates are `cargo build --release`, `cargo clippy --all-targets`, `cargo test`

- Commands run on macOS/Linux with cargo installed

## Acceptance criteria

### Must

- [x] **AC-1** Given a built workspace, when `tetris` runs one game at seed 42 with `dummy-drop` joined as a separate program, then the game ends by itself at top-out and prints a final `result points=<P> lines=<L> pieces=<X>` line.
      Verify: `cargo build --release && target/release/tetris --seed 42 --player target/release/dummy-drop 2>&1 | grep -m 1 "result points="`
- [x] **AC-2** Given a running game, when the game sends the board state each turn, then the logged board block holds 20 rows of exactly 10 cells framed by `board begin` and `board end` lines.
      Verify: `cargo build --release && target/release/tetris --seed 42 --player target/release/dummy-drop 2>&1 | awk '/^board begin/{f=1;next} /^board end$/{if(f){ok=1; exit !(r==20)}} f{r++; if(length!=10) exit 1} END{if(!ok) exit 1}'`
- [x] **AC-3** Given the same seed 42 with `dummy-random`, when the identical game command runs twice, then the two full logs are identical and each shows a finished game.
      Verify: `cargo build --release && target/release/tetris --seed 42 --player target/release/dummy-random > /tmp/tetris-a.log && target/release/tetris --seed 42 --player target/release/dummy-random > /tmp/tetris-b.log && grep -m 1 "result points=" /tmp/tetris-a.log && grep -m 1 "result points=" /tmp/tetris-b.log && diff /tmp/tetris-a.log /tmp/tetris-b.log`
- [x] **AC-4** Given a robot that answers `banana` forever and a robot that answers `left` forever even at the wall, when an answer cannot be applied, then the game logs `rejected banana` for the nonsense word and `rejected left` for the blocked move, and both games still finish with a result line.
      Verify: `cargo build --release && target/release/tetris --seed 42 --player "yes banana" 2>&1 | tee /tmp/tetris-garbage.log | grep -m 1 "rejected banana" && target/release/tetris --seed 42 --player "yes left" 2>&1 | tee /tmp/tetris-left.log | grep -m 1 "rejected left" && grep -m 1 "result points=" /tmp/tetris-garbage.log && grep -m 1 "result points=" /tmp/tetris-left.log`
- [x] **AC-5** Given a robot whose every answer is the nonsense word `banana`, when its game runs to the result line, then pieces were still placed while the log contains no `accepted` line at all.
      Verify: `cargo build --release && target/release/tetris --seed 42 --player "yes banana" 2>&1 | tee /tmp/tetris-slide.log | grep -m 1 "placed " && ! grep -q "accepted" /tmp/tetris-slide.log`
- [x] **AC-6** Given a robot that waits 2 seconds before every answer and the game started without the timer flag, when the game finishes, then the log contains no `timer nudge` line.
      Verify: `cargo build --release && target/release/tetris --seed 42 --player "while true; do sleep 2; echo drop; done" 2>&1 | tee /tmp/tetris-slow.log | grep -m 1 "result points=" && ! grep -q "timer nudge" /tmp/tetris-slow.log`
- [x] **AC-7** Given the same slow robot and the game started with `--timer 1`, when a silent second passes, then the log records `timer nudge` lines.
      Verify: `cargo build --release && target/release/tetris --seed 42 --timer 1 --player "while true; do sleep 2; echo drop; done" 2>&1 | grep -m 1 "timer nudge"`
- [x] **AC-8** Given the four scripted move fixtures, when their games finish, then 1 cleared line scores 100, 2 lines score 300, 3 lines score 500, and 4 lines score 800 on the result line.
      Verify: `cargo build --release && target/release/tetris --seed 42 --player "cat moves-100.moves" 2>&1 | grep -m 1 "result points=100 lines=1" && target/release/tetris --seed 42 --player "cat moves-300.moves" 2>&1 | grep -m 1 "result points=300 lines=2" && target/release/tetris --seed 42 --player "cat moves-500.moves" 2>&1 | grep -m 1 "result points=500 lines=3" && target/release/tetris --seed 42 --player "cat moves-800.moves" 2>&1 | grep -m 1 "result points=800 lines=4"`
